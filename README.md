# Certificate Installer

[Все релизы](https://github.com/sovenov/certificate-installer/releases) · [Скачать EXE v1.0.0](https://github.com/sovenov/certificate-installer/releases/download/v1.0.0/CertificateInstaller.exe) · [Скачать Python-скрипт v1.0.0](https://github.com/sovenov/certificate-installer/releases/download/v1.0.0/install_certificates.py) · [SHA256SUMS](https://github.com/sovenov/certificate-installer/releases/download/v1.0.0/SHA256SUMS.txt)

Пакетная установка сертификатов, списков отзыва и контейнеров с закрытыми ключами в хранилища Windows. Можно выбрать область установки и автоматически распределить объекты по хранилищам либо установить все в доверенные корневые центры сертификации.

В репозитории есть два варианта:

- **CertificateInstaller.exe** — приложение с графическим интерфейсом. Готовая сборка находится в `dist/CertificateInstaller.exe`; для запуска достаточно этого файла. Python, .NET, Visual C++ Redistributable и установка приложения не нужны.
- **install_certificates.py** — консольный скрипт для обработки всех поддерживаемых файлов рядом с ним. Нужен Python 3.8+; сторонние библиотеки не используются.

EXE — нативное 32-битное приложение C++/Win32 для Windows x86/x64. Целевая совместимость: Windows 7 SP1, 8/8.1, 10 и 11. Формат PE и обязательные импорты проверяются на совместимость с Windows 7; **реальный запуск на Windows 7 пока не проверен**. Python-скрипт предназначен для Windows 10 и 11.

## Графическое приложение

1. Запустите `CertificateInstaller.exe`.
2. Нажмите **«Добавить файлы…»** и выберите один или несколько файлов через Ctrl/Shift. Можно также перетащить файлы в окно программы.
3. Выберите расположение хранилища: **«Текущий пользователь»** или **«Локальный компьютер»**.
4. Выберите автоматическое распределение либо **«Все объекты → Доверенные корневые центры сертификации (Root)»**.
5. Нажмите **«Проверить»**, чтобы увидеть план, или **«Установить»**, чтобы выполнить импорт.

Выбранная область и режим применяются ко всем файлам и ко всем сертификатам/CRL внутри контейнеров. Файлы рядом с EXE автоматически не выбираются; подпапки не просматриваются. Повторное добавление одного пути не создаёт вторую строку. Кнопки **«Убрать выбранные»** и **«Очистить список»** меняют список файлов.

Для защищённого PFX/P12 появится отдельный диалог со скрытым вводом пароля. При неверном пароле можно повторить ввод или нажать **«Пропустить файл»**: остальные файлы продолжат обрабатываться. Контейнеры с пустым или NULL-паролем открываются автоматически. Пароли не передаются в командной строке, не попадают в журнал и не сохраняются в настройках.

Кнопка **«Проверить»** читает содержимое и показывает план без изменения целевых хранилищ и без сохранения закрытых ключей PFX/P12.

Журнал показывает полный путь файла, имя сертификата или издателя CRL, отпечаток SHA-1, результат каждого объекта и причины ошибок с кодами Windows. Кнопка **«Сохранить журнал…»** сохраняет его в UTF-8.

Для установки в область локального компьютера программа при необходимости запросит повышение прав через UAC. После подтверждения она перезапустится с выбранными файлами и настройками и выполнит импорт. При отмене UAC список остаётся в исходном окне. Если список путей слишком велик для передачи через командную строку Windows, запустите EXE от имени администратора и выберите файлы заново.

Хранилище текущего пользователя относится к учётной записи, под которой запущена программа.

## Python-скрипт

Скачайте `install_certificates.py` и положите его в папку с сертификатами. Скрипт ищет файлы **в своей папке**, независимо от текущей папки консоли. Подпапки не обрабатываются; регистр расширения не важен.

При запуске нужно сделать два общих выбора:

1. Текущий пользователь или локальный компьютер.
2. Автоматический выбор хранилища по типу объекта или установка всех объектов в `Root`.

Эти настройки действуют на всю партию. Для выхода до начала обработки в любом из двух меню введите `0`.

Пример запуска из **CMD**:

```bat
cd /d "C:\Certificates"
python install_certificates.py
```

Из **PowerShell**:

```powershell
Set-Location "C:\Certificates"
python .\install_certificates.py
```

Если используется Windows Python Launcher, вместо `python` можно указать `py -3`.

Для проверки без установки:

```powershell
python .\install_certificates.py --dry-run
```

Параметр `--no-pause` отключает ожидание Enter перед закрытием. Например, результат проверки можно записать в файл:

```powershell
python .\install_certificates.py --dry-run --no-pause > .\install-check.log
```

Пароль PFX/P12 запрашивается через скрытый консольный ввод. Неверный пароль можно ввести повторно. Ctrl+C или EOF во время запроса пароля отменяет только соответствующий файл; остальные файлы продолжают обрабатываться. Если скрытый ввод недоступен, файл пропускается без перехода к видимому вводу пароля.

Для установки в область **«Локальный компьютер»** запустите CMD или PowerShell от имени администратора. Скрипт сам не повышает права: если их нет, он завершится до установки. Для `--dry-run` повышение прав не требуется.

Коды завершения скрипта:

| Код | Значение |
|---|---|
| `0` | Обработка завершена без ошибок и отменённых PFX; также возвращается при отсутствии файлов или выборе `0` в начальных меню |
| `1` | Ошибка, отмена одного или нескольких PFX либо отсутствие необходимых прав администратора |
| `2` | Неверные аргументы командной строки |
| `130` | Прерывание выбора настроек или обработки через Ctrl+C/EOF; запрос пароля PFX обрабатывается отдельно |

## Форматы файлов

Оба варианта поддерживают следующие расширения. Тип содержимого определяется Windows CryptoAPI; расширение используется для поиска и выбора файлов.

| Расширения | Содержимое |
|---|---|
| `.crt`, `.cer`, `.der` | Сертификат X.509 в DER или PEM/Base64 |
| `.crl` | Список отзыва сертификатов в DER или PEM/Base64 |
| `.pem` | Один или несколько PEM-блоков сертификатов, CRL и PKCS#7 |
| `.p7b`, `.p7c` | Все сертификаты и CRL из контейнера PKCS#7 в DER или PEM/Base64 |
| `.sst` | Сертификаты и CRL из сериализованного хранилища Microsoft |
| `.pfx`, `.p12` | Сертификаты, цепочка и связанные закрытые ключи из PKCS#12 |

PEM-набор разбирается по блокам. Ошибка одного блока сообщается и не мешает обработать следующие корректные блоки. Обычные заголовки OpenSSL, `Bag Attributes`, `subject`, `issuer` и комментарии между блоками допускаются. Метка блока должна соответствовать его содержимому: сертификат, CRL или PKCS#7.

Отдельные PEM-блоки закрытых ключей и запросы CSR не импортируются. Для переноса сертификата вместе с закрытым ключом используйте PFX/P12.

## Выбор хранилища и повторный импорт

В автоматическом режиме действует следующая политика:

| Объект | Хранилище Windows |
|---|---|
| CA с собственной подписью | `Root` — доверенные корневые центры сертификации |
| Остальные CA | `CA` — промежуточные центры сертификации |
| Конечный сертификат | `My` — личное |
| Список отзыва CRL | `CA` — промежуточные центры сертификации |

CA определяется по Basic Constraints v2 или устаревшему v1. Сертификат без этого расширения считается конечным. Старый корневой сертификат без Basic Constraints можно установить явным выбором `Root`. Это политика программы и скрипта; автоматический мастер импорта Windows не вызывается.

В режиме `Root` все сертификаты и CRL помещаются в выбранное корневое хранилище. Используйте этот режим только для объектов, которым доверяете. Импорт сам по себе не проверяет срок действия сертификата и доверие ко всей цепочке. Для нестандартных алгоритмов, например ГОСТ, может понадобиться соответствующий криптопровайдер Windows.

Повторный сертификат без закрытого ключа пропускается. При импорте сертификата с закрытым ключом привязка к ключу добавляется или обновляется, даже если публичный сертификат уже установлен; это учитывается как установка/обновление. CRL заменяет существующий только при более свежем `ThisUpdate`: старый список не откатывает новый.

Ошибка одного объекта не останавливает остальные. Итог считает отдельные объекты, а ошибка чтения или пустого контейнера учитывается как одна ошибка файла. Файлы, отменённые при запросе пароля, считаются отдельно.

Пакетный импорт не является транзакцией: уже выполненные изменения и импортированные ключи при последующей ошибке не откатываются.

## Закрытые ключи и совместимость PFX

При установке PFX/P12 ключи сохраняются для выбранного текущего пользователя или локального компьютера. Они не помечаются экспортируемыми; существующие контейнеры ключей принудительно не перезаписываются. Настройка `Root`/автоматического режима определяет хранилище сертификатов, а расположение ключа определяется выбранной областью пользователя/компьютера.

При проверке используется `PKCS12_NO_PERSIST_KEY`: закрытые ключи открываются только в памяти и не сохраняются на диск. Целевые хранилища сертификатов не открываются.

Поддержка шифрования PFX зависит от версии Windows и криптопровайдера. На старых системах может понадобиться совместимый контейнер TripleDES-SHA1; AES256-SHA256 поддерживается не всеми версиями Windows. Неподдерживаемое шифрование может выглядеть как ошибка пароля даже при правильном вводе. Ограничение описано в [документации Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-server/certificates-and-public-key-infrastructure-pki/cannot-import-aes256-sha256-encrypted-pfx-certificate).

Совместимость EXE с Windows 7 проверяется по целевой версии PE и обязательным импортам. Это не заменяет проверку на реальной Windows 7 или виртуальной машине. Для PFX дополнительно нужен алгоритм шифрования и криптопровайдер, доступный на целевой системе.

## Исходники и сборка

Репозиторий самостоятельный: исходники приложения, Python-скрипт, сборочные файлы и тестовые фикстуры находятся в его корне. Соседние проекты не требуются.

Для сборки нужны Windows, Python 3.8+, MSVC v142/v143 и Windows SDK. На компьютере пользователя готового EXE эти инструменты не нужны.

Из корня репозитория:

```powershell
python build.py
```

Сборка использует C++14, Win32/x86, статический runtime `/MT`, `WINVER/_WIN32_WINNT=0x0601` и `/SUBSYSTEM:WINDOWS,6.01`. EXE не содержит CLR и не требует .NET. Результат — `dist/CertificateInstaller.exe`.

`build.py` ищет установленный toolset MSVC 14.2x–14.4x. По умолчанию используется SDK `10.0.22621.0`; другую установленную версию задайте через `--sdk`, каталог `VC/Tools/MSVC/<версия>` — через `--msvc`. Toolset v145/14.5x для этой сборки не принимается.

После сборки скрипт запускает нативные регрессионные тесты и проверяет PE: архитектуру x86, подсистему Windows 6.1, отсутствие CLR, внешних runtime-зависимостей и обязательных импортов проверяемых API Windows 8+. Отчёт сохраняется в `build/pe-audit.txt`.

Альтернативный путь — CMake с MSVC, например Visual Studio 2022:

```powershell
cmake -S . -B build/cmake -G "Visual Studio 17 2022" -A Win32 -T v143
cmake --build build/cmake --config Release
cmake -E chdir build/cmake ctest -C Release --output-on-failure
```

CMake также использует C++14, статический runtime и целевую подсистему Windows 6.1. Готовые файлы этой сборки находятся в `build/cmake/Release/`. Автоматический аудит PE выполняется путём `build.py`.

## Тесты

Python-регрессии запускаются из корня репозитория без сторонних пакетов:

```powershell
python -B -m unittest -v test_install_certificates
```

Проверка интерфейса требует собранного `dist/CertificateInstaller.exe` и интерактивной сессии Windows:

```powershell
python -B ui_smoke_test.py
```

Она проверяет файловый drop, выбор нескольких файлов, Unicode-пути, настройки партии, план импорта, пароли PFX, пропуск файла, сохранение журнала и работу списка. Журналы и снимки окон сохраняются в `build/`.

Нативные и Python-тесты записывают сертификаты только во временные MEMORY-хранилища. Импорт PFX в тестах принудительно использует `PKCS12_NO_PERSIST_KEY` даже для сценариев установки: MEMORY-назначение само по себе не предотвращает сохранение ключей при `PFXImportCertStore`. GUI-тесты выполняют только dry-run.

Фикстуры содержат публичные синтетические сертификаты, искусственный RSA-ключ и опубликованный тестовый пароль. Реальных пользовательских секретов в них нет. Проверка переноса привязки ключа использует синтетические свойства без создания постоянных контейнеров. Реальные системные хранилища и постоянные ключи автоматизированные тесты не изменяют; UAC и фактический запуск на Windows 7 требуют отдельной ручной проверки.
